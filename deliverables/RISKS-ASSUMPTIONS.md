### RR-01 — Groq free-tier model deprecation or rate-limit changes

- **Likelihood / impact:** High / High (settled in round 10, O-08).
- **Mitigation:** switch provider by configuration — `LLM_PROVIDER` plus that provider's variables, one OpenAI-compatible adapter, no code change (a configuration swap, not automatic failover); HTTP 429 → "System is busy due to high demand. Please try again shortly."; 401/404 → "System configuration error. Please contact support."; the socket stays open.
- **Early detection:** the live smoke test (`uv run pytest -m live_llm`) and the manual checks in commits 2 and 5; the distinct 401/404/429 messages make the cause visible. No startup "pre-flight" model ping: it burns free-tier quota and can block startup when rate-limited, and deep health checks were rejected.
- **Evidence:** E05 — the template's defaults are already stale (`llama-3.3-70b-versatile` is Enterprise-tagged and not on the free plan; `gemini-2.0-flash` is shut down; OpenRouter's free llama model is absent; Groq lists a shutdown date for `llama-3.1-8b-instant`).

### RR-02 — Deliberation-model latency, token exhaustion, empty responses

- **Likelihood / impact:** Medium / High.
- **Mitigation:** `reasoning_effort` "low" through `GROQ_EXTRA_PARAMS` (set in the Groq block of `.env.example`, not hard-coded, sent only when `LLM_PROVIDER=groq`); `max_tokens` 1500; the 8 s timer from request start to the first chunk of any kind, so a deliberation-only chunk stops it and long deliberation is bounded by the 30 s turn timeout (round 10, O-09, O-21); empty output → "AI service temporarily unavailable. Please try again." (consolidated catalog, round 11); `finish_reason == "length"` → "The answer was cut short. Please ask a narrower question."
- **Early detection:** adapter tests for the first-token timeout and empty-`choices` handling; the live smoke test for real latency.
- **Open:** whether `max_tokens` bounds deliberation tokens (U-03) and whether they count toward rate limits (U-04).

### RR-03 — OCR paragraph-threshold drift across environments

- **Likelihood / impact:** Medium / Medium.
- **Mitigation:** RapidOCR 3.9.2 pinned with its bundled ONNX models; fixed 300 dpi render; the 2.0× median-gap threshold sits between the measured in-paragraph gaps (0.7×–1.4×) and paragraph gaps (2.9×–3.9×) (E02).
- **Early detection:** the `model`-marked ingestion integrity test asserts 6 chunks from the scan and 42 in total — run on each machine that ingests (no CI exists); the boxes-fixture unit test pins the grouping logic itself.
- **Evidence:** E01 (300 dpi: 18 lines, minimum confidence 0.984), E02.

### RR-04 — First-run embedding-model download fails

- **Likelihood / impact:** Medium / High.
- **Mitigation:** the README states the network need (~130 MB on first run) and that an air-gapped machine needs a pre-warmed Hugging Face cache; the ingestion library raises a domain error that the CLI maps to exit 1; a CLI check for cached model weights†.
- **Early detection:** the `model`-marked tests exercise the download. The default offline suite never needs the model, so tests pass air-gapped — but ingestion itself still needs network on its first run.
- **Evidence:** E01 (first load including download 21.7 s), K03.

### RR-05 — Evaluator has no Docker for Qdrant

- **Likelihood / impact:** Medium / Critical.
- **Mitigation:** embedded/local mode stays rejected (Python-side filters, blocks the event loop); the Qdrant connection is validated in the lifespan; the startup failure message names the required `docker run` command†; README §1 gives the command.
- **Early detection:** the lifespan check fails fast (uvicorn exit code 3) before any WebSocket is accepted; the ingestion CLI pings Qdrant before loading models.
- **Evidence:** the brief's `.env.example` ("Qdrant in Docker: docker run -p 6333:6333 qdrant/qdrant"); brief §7 measured facts (Docker is installed on the candidate's machine; the evaluator's machine is unknown).

### RR-06 — Default macOS Python too old

- **Likelihood / impact:** High / High.
- **Mitigation:** `requires-python = ">=3.11"`; every README command runs through `uv sync --python 3.12` / `uv run`; a hard `sys.version_info >= (3, 11)` check at the server and CLI entry points†.
- **Early detection:** the hard version check† fails immediately with a clear message.
- **Evidence:** brief §7 measured facts (system `python3` 3.9.6 and uv 0.12.18 on the candidate's machine); K02 verified (fastapi, qdrant-client, sentence-transformers and openai need ≥ 3.10); K07 (`TaskGroup` and `asyncio.timeout` need 3.11).

### RR-07 — RBAC filter bypass or document leakage

- **Likelihood / impact:** Low / Critical.
- **Mitigation:** the filter is built in code from validated claims and evaluated inside `query_points`; `access_level` stored as int; no post-retrieval filtering; restricted chunks never reach the LLM; security does not depend on the prompt.
- **Early detection:** `qdrant` tests asserting 12 / 18 / 24 / 30 visible chunks and no forbidden `source_file`; the filter-structure unit test; the manual checklist (the automated golden-set eval was cut in round 11; E03 measured 0 restricted-file leaks).

### RR-08 — Event-loop starvation from synchronous calls

- **Likelihood / impact:** Medium / High.
- **Mitigation:** model load and `encode` via `asyncio.to_thread` (from commit 4); async Qdrant and OpenAI clients; the mock fetches use `asyncio.sleep`.
- **Early detection:** one unit test patches `asyncio.to_thread` in the embedder module and asserts `encode` is dispatched through it (round 11; the heartbeat-and-mutation harness was dropped).
